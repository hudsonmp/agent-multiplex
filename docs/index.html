agent - multiplex

A live web view for driving Claude Code and gemini-cli side-by-side in parallel git worktrees on the same repo. Watch both agents work the same task, interject in either one, and replay raw transcripts after the fact.

What it is

a multi-agent harness, not an IDE

Two terminal panes in a browser. Each pane is a real pseudo-terminal attached to a real agent — the left one to claude, the right one to gemini — running in its own git worktree off the same repo. You type into either pane as if it were your terminal; both agents work the same codebase at the same time without trampling each other's commits.

Raw bytes from each PTY are saved to disk with millisecond timestamps, so the session becomes a research artifact you can grep, diff, and replay later.

posture Localhost-only. No authentication. Designed for one person at one laptop, comparing how two agents reason about the same problem.

Prerequisites

things this assumes you already have

  • Node.js 20+ — needed because node-pty compiles a native addon. On macOS run xcode-select --install first.
  • git — for worktree management.
  • claude on $PATH — Anthropic's Claude Code CLI.
  • gemini on $PATH — Google's open-source gemini-cli (npm i -g @google/gemini-cli).
graceful degradation If only one of the two CLIs is installed, the missing pane shows exited (127) and the rest of the session works normally. You don't have to install both to try it.

Install

three commands · sixty seconds

# clone
$ git clone https://github.com/hudsonmp/agent-multiplex.git
$ cd agent-multiplex

# install deps (node-pty compiles natively here)
$ npm install

# start backend (:4040) + frontend (:5173) together
$ npm run dev

Then open http://localhost:5173.

First session

a walkthrough · roughly thirty seconds

  1. Point it at a repo

    Type any absolute path to a local git repo in the launcher — e.g. /Users/you/your-project — and click load branches. The dropdown populates.

  2. Pick a base branch

    Both agents will branch off this. The defaults — mux/claude-<timestamp> and mux/gemini-<timestamp> — are fine; they keep the harness's branches clearly out-of-band from your normal work.

  3. Launch

    The backend creates two worktrees at <repo>-mux-claude-<id>/ and <repo>-mux-gemini-<id>/, spawns a PTY in each, and routes you to the split-pane view. Both agents boot in their own worktree.

  4. Drive them

    Click into either pane and type. Drag the divider to rebalance. Both terminals reflow on browser resize. Anything you type is sent over a websocket; anything they print is broadcast back and tee'd to disk.

  5. Close cleanly

    Hit close session. Both PTYs are killed, both worktrees are removed (git worktree remove --force), and the manifest is marked closed_at. Log files stay.

Data on disk

where the artifacts live · what they contain

~/.agent-multiplex/ └── sessions/ └── <session_id>/ ├── manifest.json ┄ id · created_at · closed_at? · worktree paths · exit codes ├── claude.log ┄ raw PTY bytes · \x1e<unix_ms>\x1e timestamp markers └── gemini.log ┄ same

The timestamp markers use ASCII \x1e (Record Separator) because that byte never appears in ANSI escape sequences or normal terminal output — so the markers can be stripped cleanly without colliding with anything the agents emit. To replay a transcript: 

$ cat ~/.agent-multiplex/sessions/<id>/claude.log \
      | perl -pe 's/\x1e\d+\x1e//g'

When it breaks

three problems you'll probably hit

node-pty fails to build You're missing build tools. On macOS: xcode-select --install. On Linux: apt-get install build-essential python3. Then rm -rf node_modules and npm install again.
pane shows command not found The PTY can't see the agent binary on $PATH. The server augments PATH with ~/.local/bin, ~/bin, /opt/homebrew/bin, and the usual system dirs; if your CLI is somewhere else, symlink it into one of those.
worktrees pile up after a crash If the backend dies mid-session, the worktrees outlive it. Clean up manually: git worktree list, then git worktree remove --force <path> for each -mux-* entry.
